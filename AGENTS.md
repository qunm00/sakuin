## Learned Workspace Facts

- Sakuin is a Rust library (not a binary crate) for indexing Markdown workspaces into a SQLite database.
- Documentation is split into `docs/design.md` (architecture & design) and `docs/plan.md` (implementation roadmap).
- Core dependencies: `rusqlite` (bundled SQLite), `pulldown-cmark` 0.13 (Markdown parsing, incl. native wikilinks via `Options::ENABLE_WIKILINKS`), `notify` + `notify-debouncer-full` 0.7 (file watching), `serde` + `yaml_serde` (frontmatter), `sha2` + `hex` (hashing), `chrono` (timestamps), `rusqlite_migration` (migrations), `ignore`, `log`.
- SQLite schema includes tables: `files` (relative_path, absolute_path, hash, frontmatter, size_bytes, modified_at, indexed_at), `headings` (level, text, anchor, position), `links` (link_type, target, anchor, text, position), `tags` (tag), and an FTS5 virtual table `fts` (file_id, title, body). Heading/link `position` fields are absolute byte offsets into the original file (`content_start + range.start`, since pulldown-cmark ranges are body-relative).
- `IndexStore` writes per file via `set_headings`/`set_links`/`set_tags`/`set_fts`; each method deletes the file's old rows and inserts fresh ones in the same transaction.
- The `links.link_type` column stores lowercase strings (`inline`, `reference`, `wikilink`, `autolink`, `image`), serialized via `LinkType::as_str()` and parsed back by the shared `pub(crate) link_type_from_str` used by both store and query.
- Query filters treat `None` as "no filter" (e.g. `files(None)` for all files, not `"*"`); optional filters use the SQLite idiom `WHERE (?1 IS NULL OR column = ?1)`.
- Schema migrations are SQL files in `migrations/`, embedded at compile time via `include_dir` and applied with `rusqlite_migration`; connections open in WAL mode with `foreign_keys=ON`.
- Module structure under `src/`: `helpers.rs` (shared helpers), `scanner/`, `indexer/`, `watcher/` (each a `mod.rs` folder, matching `parser/` and `store/`), `query.rs`. Example binary at `examples/basic-index.rs`; CI (GitHub Actions) runs `cargo fmt --check`, `cargo clippy -D warnings`, `cargo build --all-targets`, `cargo test` on push/PR to `main`.
- Scanner and subtree walks use `ignore::WalkBuilder` with `standard_filters(true)` (respects `.gitignore`) and `hidden(true)`, filtering to `.md` files (case-insensitive); relative paths are sorted deterministically by the shared `pub(crate) sort_relative_paths` in `src/helpers.rs`.
- Phase 4 file watching: `src/watcher/mod.rs` runs a `notify-debouncer-full` watcher (200ms debounce) on a background thread and emits `WatchEvent::{Changed,Renamed,Removed}` with relative paths over an mpsc channel (hidden paths and non-`.md` create/modify events skipped; no filesystem calls in the watcher — file-vs-dir decisions live in the indexer); `src/indexer/mod.rs` exposes `Indexer::open/scan_full/listen/poll/query`, funnels `Changed`/`Renamed` into `index_path` (dir → `index_subtree` walk via `ignore::WalkBuilder`, file → single parse), `remove_from_index` cascades deletes for removed directories, and `poll()` falls back to a full re-scan if the watcher thread died.
- No Rust toolchain exists on this machine — `cargo`/`rustc` cannot be run, so Rust changes are unverified locally (they were compile-checked by the user during the Phase 4 session). Verified `notify-debouncer-full` 0.7 API: `new_debouncer(timeout, tick_rate, handler)` takes 3 args; `DebouncedEvent { event: notify::Event, time: Instant }` (no `DebouncedEventKind`); renames arrive as `EventKind::Modify(ModifyKind::Name(RenameMode::{From,To,Both,Any}))` with sub-kind enums under `notify::event`; `Debouncer` implements `Watcher` directly (`.watch()` not `.watcher().watch()`); `notify::Event` builder uses `add_path` (not `with_paths`).
